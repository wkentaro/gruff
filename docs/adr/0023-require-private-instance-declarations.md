# Require private instance declarations

GR015 requires a class-body annotation for every private attribute a method stores on its receiver. GR012 already requires one for public attributes. Its own ADR (0015) treats an underscore-prefixed name as enough for internal state, since GR012's concern is the public data interface. GR015's concern is the type checker. ty infers an undeclared attribute's type from every value assigned to it, so `self._flag = False` followed by `self._flag = "oops"` gives `bool | str` and no error. With `_flag: bool` in the class body, the second store is an error.

The scope is GR012's minus the public-name filter, and GR012 keeps public names, so a store gets at most one finding. Following ADR 0005, it gets its own code instead of widening GR012: a project can want declared public data without declaring every private field. Both rules share one store scanner, so their receiver, method, declaration, and property handling stay the same. Private means what it means in the other non-public rules: a leading underscore and no trailing one, since dunder and sunder names such as `__dict__` and `_value_` keep a protocol contract. Name-mangled names are checked, because Python mangles the class-body annotation and the store the same way.

An annotation inside a method does not count. ty already treats `self._x: T = v` in a method as a declaration, so moving it changes no type. The rule asks for the class body anyway, so a reader finds a class's fields in one place, as GR012 does for public data.

On osam, GR015 flags 31 stores of 20 names: 14 names annotated inside `__init__` and 6 with plain stores. Declaring all of them left `ty check` clean except one: `_Process` was defined after the class, so the class-body annotation raised `NameError` on import under Python 3.10. Quoting it fixed both. The six plain stores got narrower types, such as `Unknown | LockType` becoming `LockType`. On labelme, the trial counted 146 findings among 246 private attributes. The rule doc covers forward references and `Final`, the two fixes that need more than moving a line. GR015 joins the opinionated tier, because some projects will see declaring private state as busywork.
