# Flag single-consumer module bindings

GR011 flags a non-public module binding — a direct child of the module body assigning a plain underscore-prefixed name to a value with no call expression — when every read of that name sits inside exactly one module-level function or method, so a value that serves one definition but lives at module scope is decided as a lexical fact. The candidate comes from a verified review correction in labelme PR #2585, where a `Final` dict read only by one method was moved into that method under the house rule that scopes a value to its usage site, and from the observation that Ruff `PLR2004` drives agents to name every magic value and that they reflexively hoist the name to module scope. The trial recorded on issue #74 ran the shape as briefed over the six reference repositories — labelme, gdown, imgviz, osam, video-cli, imshow — and hand-labelled all 59 findings: 55 review-blocking, 4 intentional module constants, and one cross-module case ruled review-blocking because a test importing a non-public name is the importer's defect. Every intentional constant was a memoised call result — a YAML load, a numpy template, a colormap, a BPE tokenizer — whose consumer runs repeatedly, so moving it changes runtime cost rather than scope. Requiring the value to be call-free removes all four and nine review-blocking findings whose values happened to call, leaving 46 findings at 100% precision. That gate is chosen over any runtime-cost heuristic because it is decidable from syntax alone and keeps every literal-valued finding. Review of the implementation found the one call-free shape the gate misses: a module-level accumulator, `_cache = {}` filled by its consumer across calls, which a move would reset on every call. Two syntactic carve-outs close it without a mutability model: an empty list or dict display is not a candidate, and a subscript or attribute store or delete whose chain leads back to the name counts as a read outside the consumer. A non-empty container mutated only through a method call is left to `# noqa`, since `append` and `get` are indistinguishable to a lexical walk and the trial corpus held none. Double-underscore names are not candidates either, because a class body mangles `__name` to `_Class__name` and a method that appears to read the module binding raises `NameError` instead. It is the first rule in this linter that resolves references rather than reading one statement, and the walk it needs — bindings and reads per name across function, class, lambda, and comprehension scopes within one module — lives in the rule module until a second rule shows what a shared helper should look like. The count of 46 sits below the 50-finding floor the GR004 sweep set; the rule ships on the precision figure, as GR010 shipped on owner taste, and remains opt-in while repository trials establish that the move reliably reduces review work.

The consumer is a `def` or `async def` that is a direct child of the module body or of a module-level class body, and only its body is the usage site. Decorators, default values, and parameter and return annotations evaluate at definition time, before a binding moved into the body would exist, so a read there keeps the binding at module scope; the trial confirmed each of those arms with a corpus example, as it did module-level reads and a `global` declaration that lazily builds a cached session. A read from a nested function, a lambda, or a comprehension inside the consumer counts as the consumer's read: comprehensions are real scopes in Python 3, and four trial findings reached the binding only through one, three of them plain single-function constants a reviewer would move; nested `def` and `lambda` follow by the same closure argument and were unexercised. Definitions nested in a module-level `if` or `try`, methods of nested classes, and functions inside functions are not consumers, so a read from one exempts the binding; that costs recall only. The brief's six rebinding and shadowing exemptions collapse into one condition, that the name has exactly one binding site in the whole module, which is at least as conservative as the six and needs one counter. The brief's `TYPE_CHECKING` module skip is dropped because a binding inside that block is not a direct module child and a read inside it is a module-level read, both already exempt; the `globals`, `vars`, `eval`, and `exec` skip is kept and matches the builtin name only, since matching attribute access too let Qt's `.exec()` hide eight findings in the trial. A name listed as a string in `__all__` is exempt, unexercised in the corpus but the clearest statement that the name has outside consumers.

The rule reads one module at a time and cannot see a cross-module import of a non-public name; the labelme test that parametrizes over `_LOGGER_LEVELS` is the one such case the trial found. The rule doc names Ruff `PLC2701` as the companion that flags the importing side and `# noqa` as the way to record a deliberate test-only export. With `_A = 1` and `_B = _A + 1` read only by one function, the first run flags `_B` alone and the next run flags `_A`; the cascade is accepted and documented rather than predicted, as GR009 already ships one-per-run behavior for nested trailing ifs. Autofix stays out because the moved binding's spelling — whether it keeps its underscore, its position in the body, and its place among sibling constants — is a human choice.
