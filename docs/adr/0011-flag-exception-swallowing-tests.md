# Flag exception-swallowing tests

GR008 flags an `except` clause inside a test definition whose body only passes, returns, or skips, so a test that cannot fail is decided as a syntactic fact rather than a judgement about assertion quality. The criterion comes from the 17-repo, 1.09 MLOC evaluation recorded in issue #54, where this narrowed form measured 100% precision over its sample: every labeled instance was a defect. It is the survivor of the general "every test asserts" candidate, which measured 23% and is rejected for good — assertion helpers and exception-as-assertion smoke tests dominated its false positives, and a bare-call smoke test is legitimate precisely because an unexpected exception still fails it. Only the swallowing handler removes that implicit assertion, so only the swallowing handler is flagged.

The measurement freezes the scope. A handler body qualifies when each of its statements, after an optional docstring, is one of five forms: `pass`, an `...` expression statement, a bare `return`, a `pytest.skip(...)` call, or a `self.skipTest(...)` / `cls.skipTest(...)` call. Skip calls count in their qualified spellings only; gruff resolves no imports, so `from pytest import skip` followed by a bare `skip("flaky")` is not a finding, and widening that would mean either import resolution or guessing at a bare name. A test definition is a function or method whose name starts with `test` in a file named `test_*.py` or `*_test.py` and not lexically nested inside another function's body, every `try` lexically inside it counts at any depth, and each swallowing handler is its own finding, so a sibling that re-raises grants no exemption. The 100% figure was measured on the `pass` and `pytest.skip` handler forms recorded in #54; the `...`, bare-`return`, and `skipTest` spellings are semantic equivalents re-derived in #59, not separately measured. `contextlib.suppress(...)` in a test has the same semantics but was never measured; per ADR-0005 it gets its own rule code if evidence lands, not a silent widening of this one.

Existing linters reach parts of this shape but not the whole of it. Ruff `S110` and `S112` flag try-except-pass and try-except-continue only for bare `except:` and `Exception`/`BaseException` handlers by default (`check-typed-exception = false`), and neither is scoped to tests; `SIM105` recommends the `contextlib.suppress` rewrite that this rule treats as evasion rather than a repair; and flake8-pytest-style `PT017` covers the complementary assert-in-except shape, which composes with GR008 because assert-bearing handlers are exempt here. The delta GR008 adds is the skip-call and bare-return forms, scoped to test definitions.

One exclusion was decided after the measurement. When a `try` carries an `else` clause, a handler that makes no skip call — whose body only passes, `...`s, bare-returns, or holds only a string literal — is outside the rule, because the `else` block runs only when nothing was raised and is therefore where the hand-rolled `assertRaises` idiom puts its `raise AssertionError(...)`. Such a test does fail when the expected exception is absent, so the handler's `pass` is the correct spelling and not a swallow. A handler that skips is still a finding on an `else`-carrying `try`, since the skip path never reaches the `else`. The `else` body itself is not inspected, so a do-nothing handler under an `else` that raises nothing escapes the rule — an accepted recall cost, unmeasured. No surviving artifact records how the corpus treated the `else` form, the prototype scripts being gone, so the exclusion is decided on semantics rather than on data; an exclusion can only remove findings, and every sampled finding was a true positive, so measured precision cannot fall, while the recall it costs is unmeasured.

Several expansions were considered and deferred pending their own corpus measurement, since each would admit findings the 100% figure does not cover: a `return None` written with an explicit value, `raise unittest.SkipTest(...)` as the unittest-native spelling of a skip, `pytest.xfail(...)` called from inside a handler, and a `continue` or `break` in an `except` body inside a loop. Three over-reaches are accepted as shipped. The visitor descends into a class nested inside a test function, so a swallowing handler in a helper class defined there is flagged, which is the right answer for the code a runner reaches through the test. A `test*` method of any class not nested inside a function is treated as a test whether or not a runner would collect that class — the enforced gate is lexical, so a method of a class inside another class is flagged too — since collectability depends on configured naming patterns and base classes that a syntactic rule cannot see; the alternative, flagging nothing outside `Test*`-named classes, would miss unittest subclasses named for their subject. And a `try` whose body ends in an unconditional failure — a `raise`, a `self.fail(...)`, a `pytest.fail(...)` — before a handler narrow enough to leave that failure uncaught is flagged all the same, although the escaping `AssertionError` does fail the test; the rule reads the handler and not the body it guards, and `# noqa: GR008` is the escape.
