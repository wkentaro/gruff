# Require non-public inputs

GR002 flags each defaulted fixed caller-supplied input to a non-public module-level function or method. The shared non-public boundary includes `_name` and `__name` definitions, with double-leading names mangled in class scope, while excluding ordinary, trailing-underscore, sunder, and dunder definitions. Requiring callers to supply every value makes non-public behavior explicit without caller analysis; the specification sweep found about 57 affected definitions across the reference repositories. Implicit method receivers and variadic parameters remain excluded. The rule remains opt-in while repository trials establish that required non-public inputs reliably reduce review work.

GR002 is now `no-uniform-non-public-defaults`, which supersedes the blanket ban above. A labelme trial of the ban after ADR 0016 required 208 explicit arguments for the one helper `new_action`. Most of those arguments repeated a default that only a few calls override. The rule now reports a default only when the calls in its module all treat it the same way: none passes it, or every one passes it. Only definitions whose own name is non-public are checked, because those are the ones whose calls all sit in the same module, and that keeps the rule within Gruff's single-file analysis. A default on an ordinary name inside a non-public module stays allowed, because other private modules may call the definition and the default holds the value they share.
