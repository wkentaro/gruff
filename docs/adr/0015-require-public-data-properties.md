# Require public data properties

GR012 implements the public instance-data policy requested in [issue #82](https://github.com/wkentaro/gruff/issues/82). It pairs direct receiver-store detection with Ruff SLF001 for external backing-field access, because that established companion already catches both reads and writes from a same-module caller of a non-public class. Duplicating it would add a second access policy with different exceptions. A same-class setter makes a public write explicit; a getter alone does not. Internal state only needs an underscore-prefixed name. The rule remains opt-in and offers no autofix because both renaming and introducing a descriptor can change callers' contracts.

The trial recorded on the issue found 74 store sites across 369 Python files at six pinned repository revisions. Eight writes to declared dataclass fields and one inherited standard-library field were concrete compatibility cases. Suppression is chosen over exempting whole decorated classes or subclasses: the latter would also hide ordinary application state in Qt widgets and plugin subclasses. Class-body declarations and generated constructors are outside the source shape, while explicit receiver stores remain subject to the policy. Imported or inherited descriptors, aliases, and runtime rebinding are not inferred. The rule doc records these limits so adoption can be incremental without guessing framework behavior.

## Explicit instance data refinement

[Issue #85](https://github.com/wkentaro/gruff/issues/85) renames GR012 to `explicit-instance-data` and supersedes the suppression-first policy for declared fields above. An annotation directly in the same class body declares public instance data, with or without a default, independently of decorators or bases. This accepts explicit writes in ordinary classes, dataclasses, attrs classes, and Pydantic models without a framework whitelist. The downstream trial exposed unnecessary pass-through properties and suppressions on already declared data; declaration shape expresses the contract without adding runtime machinery.

Recognizable `ClassVar` and `InitVar` annotations, including quoted forms and direct import aliases, describe class state or constructor inputs and do not exempt instance stores. A locally recognized getter-only property takes precedence over an annotation. Frozen-class and `Final` enforcement belong to other tools. Unannotated descriptor assignments, framework factories, inherited declarations, and runtime rebinding are not inferred. Inherited contracts remain valid reasons for suppression; same-file bases receive no special treatment that would change when code moves between modules.

Private storage remains appropriate for internal state; properties serve validation and read/write control. Dataclasses remain useful for generated initialization, but are not required to declare a data interface. This narrows an existing rule rather than introducing an independently adoptable scope expansion, so GR012 and its configuration remain stable. Any separate rule about classes mixing many fields and substantial behavior must receive a new code under ADR 0005.
