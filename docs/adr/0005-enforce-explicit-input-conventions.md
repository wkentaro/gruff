# Require explicit input calling conventions

GR001 flags each fixed caller-supplied input to a module-level function or method that is positional-or-keyword, whatever the definition is named. Positional-only (`/`) and keyword-only (`*`) inputs are accepted because both declarations make the calling convention local, deterministic, and runtime-enforced, while ordinary positional-or-keyword inputs remain ambiguous. The rule covers every callable rather than private definitions alone: an explicit calling convention is at least as valuable on a public contract, and scoping the rule to underscored names invited dropping the underscore to dodge it. GR002 deliberately stays private-only because a default on a public callable is the contract external callers depend on. Implicit method receivers and variadic parameters are excluded. The rule remains opt-in while repository trials establish that explicit input calling conventions reliably reduce review work.
